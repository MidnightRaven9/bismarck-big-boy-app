# Maintainer guide

## Web and Android releases

GitHub Pages serves the web app from `main`. The Android APK is a Bubblewrap Trusted Web Activity generated by PWABuilder CloudAPK. It opens the hosted web app, so changes to hosted screens and native launch assets have separate release steps.

The Android wrapper uses `#101114` for its launch background. The packaging script replaces the dedicated splash drawable at each density using [`assets/startup/android/`](../assets/startup/android), then re-signs the APK and AAB. The web splash uses the matching artwork in [`assets/startup/big-boy-bismarck.webp`](../assets/startup/big-boy-bismarck.webp). Android and the browser control the handoff to the hosted app.

### Build a candidate

Use a JDK and Android SDK Build Tools with `aapt2`, `zipalign`, and `apksigner`. Set `ANDROID_HOME` to the SDK directory or put those tools on PATH. Supply the existing signing credentials using the names in [`.env.example`](../.env.example). Keep local signing files outside directories served over HTTP. Packaging sends the keystore to the configured CloudAPK provider. See the [security review](../SECURITY_REVIEW.md) for details.

```bash
python3 scripts/package-android.py --output-dir /path/to/new-build
```

The output directory must have unused artifact filenames. Verify the candidate’s application ID, signature, and splash resources before replacing release assets. To test the full launch experience on a device, the APK’s start URL must serve the intended web version. Running the packaging script without `--output-dir` uploads to the configured GitHub Release.

### What CI does

- [Validate](../.github/workflows/validate.yml) runs on pull requests and pushes to `main`. It needs no signing credentials and has no publishing step.
- [Auto-Update Android Package](../.github/workflows/auto-package.yml) runs on a six-hour schedule and supports manual dispatch. It compares the app-shell inputs with `APP_SHELL_HASH.txt` before repackaging. A separate job validates deal data before committing changes to `facebook_deals.json`.

## Screenshot refresh

The README uses 390 × 844 Chromium captures of the app. The gallery also links to a capture of the full history section. Install the browser tooling from the [README](../README.md#checks-and-releases), start the local server, and run:

```bash
APP_URL=http://127.0.0.1:8000/ node scripts/capture_screenshots.js
```

The script writes to [`assets/screenshots/`](../assets/screenshots). Review all captures before committing them. Keep repository graphics in [`docs/assets/`](assets); the README banner is also sized for GitHub’s social preview.
